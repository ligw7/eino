## 组件（Component）

Eino框架中的组件（Component）是功能的原子单元，代表了可复用和可组合的构建块。每个组件都定义了明确的输入、输出类型以及可选的配置选项（Options），并遵循特定的执行范式。框架提供了丰富的组件抽象，如模型（Model）、工具（Tool）、提示模板（ChatTemplate）、检索器（Retriever）等。

组件的核心是其接口定义。例如，`BaseChatModel`接口定义了生成文本的基本能力，它要求实现`Generate`和`Stream`两个方法，分别用于同步生成和流式生成。这使得任何实现了该接口的模型实例（如OpenAI模型）都可以无缝地集成到Eino的编排系统中。

```go
// BaseChatModel defines the basic interface for chat models.
type BaseChatModel interface {
    Generate(ctx context.Context, input []*schema.Message, opts ...Option) (*schema.Message, error)
    Stream(ctx context.Context, input []*schema.Message, opts ...Option) (
        *schema.StreamReader[*schema.Message], error)
}
```

另一个关键组件是`InvokableTool`，它代表了一个可以被调用的工具。工具不仅包含其元信息（通过`Info`方法获取），还包含其执行逻辑（通过`InvokableRun`方法）。这使得编排系统可以在运行时决定调用哪个工具，并将结果反馈给模型。

```go
// InvokableTool the tool for ChatModel intent recognition and ToolsNode execution.
type InvokableTool interface {
    BaseTool
    InvokableRun(ctx context.Context, argumentsInJSON string, opts ...Option) (string, error)
}
```

这些组件作为独立的功能单元，是构建更复杂应用的基础。它们的实现对编排系统是透明的，用户只需关注其接口契约。

## 编排（Orchestration）

编排（Orchestration）是Eino框架的核心，它负责将独立的组件连接起来，形成一个有向的、可控的数据流。Eino提供了三种主要的编排API：链（Chain）、图（Graph）和工作流（Workflow），它们都实现了`Runnable`接口，可以在编译后通过`Invoke`、`Stream`等方法执行。

编排系统将组件实例视为图中的节点（Node），并将数据流通道视为边（Edge）。通过`AddEdge`或`AddInput`等方法，可以定义节点间的依赖关系和数据流向。例如，一个简单的链式编排可以将一个`ChatTemplate`的输出连接到一个`ChatModel`的输入。

```go
chain, _ := NewChain[map[string]any, *Message]().
           AppendChatTemplate(prompt).
           AppendChatModel(model).
           Compile(ctx)
```

更复杂的图（Graph）编排支持循环、分支和并行执行。`GraphBranch`允许根据运行时条件将执行流导向不同的节点，而`Parallel`结构则允许多个节点并发执行。工作流（Workflow）在图的基础上，提供了更高级的字段级数据映射能力，允许将一个节点输出的特定字段映射到另一个节点输入的特定字段。

编排系统在编译时会进行类型检查，确保连接的节点输入输出类型兼容。它还负责处理流式数据的自动拼接、合并和复制，以及选项（Options）的传递和回调（Callbacks）的注入，极大地简化了复杂AI应用的开发。

## 回调（Callbacks）

回调（Callbacks）系统是Eino框架的切面（Aspect）机制，它允许在编排执行的生命周期中注入自定义逻辑，而无需修改组件或编排本身的代码。这对于实现日志记录、性能监控、追踪（Tracing）等横切关注点（cross-cutting concerns）至关重要。

Eino支持五种回调时机（Timing）：
- `OnStart`: 在组件执行前调用。
- `OnEnd`: 在组件成功执行后调用。
- `OnError`: 在组件执行出错时调用。
- `OnStartWithStreamInput`: 在流式输入组件开始执行前调用。
- `OnEndWithStreamOutput`: 在流式输出组件执行结束后调用。

开发者可以通过`HandlerBuilder`创建一个回调处理器（Handler），并将其作为选项传递给`Invoke`等方法。框架会自动在正确的时机调用处理器中的相应函数。

```go
handler := NewHandlerBuilder().
  OnStartFn(func(ctx context.Context, info *RunInfo, input CallbackInput) context.Context) {
        log.Infof("onStart, runInfo: %v, input: %v", info, input)
    }).
  OnEndFn(func(ctx context.Context, info *RunInfo, output CallbackOutput) context.Context) {
        log.Infof("onEnd, runInfo: %v, out: %v", info, output)
    }).
  Build()
  
compiledGraph.Invoke(ctx, input, WithCallbacks(handler))
```

此外，Eino还提供了`HandlerHelper`，允许为不同类型的组件（如`ChatModel`、`Prompt`）设置特定的处理器，从而实现更精细化的控制。

## 流式处理（Stream Processing）

流式处理（Stream Processing）是Eino框架的关键特性，它能够自动管理从大语言模型（LLM）实时生成的流式数据块。框架通过`schema.StreamReader[T]`泛型类型来抽象流式数据，用户可以通过`Recv()`方法逐个接收数据块。

Eino的编排系统是“流感知”（stream-aware）的，它能自动处理流式数据在不同组件间的转换。例如，当一个流式输出的`ChatModel`连接到一个只接受非流式输入的`ToolsNode`时，编排系统会自动将流式数据块拼接（concatenate）成一个完整的对象。反之，它也能将非流式数据包装（box）成流式数据。

编排系统支持四种流式处理范式：
- `Invoke`: 接受非流式输入，返回非流式输出（ping => pong）。
- `Stream`: 接受非流式输入，返回流式输出（ping => stream out）。
- `Collect`: 接受流式输入，返回非流式输出（stream in => pong）。
- `Transform`: 接受流式输入，返回流式输出（stream in => stream out）。

这种设计使得组件的流式范式对用户是透明的。即使一个组件只实现了`Stream`方法，用户仍然可以调用`Invoke`方法，框架会自动完成流式到非流式的转换。

## 选项（Options）

选项（Options）模式是Eino框架中统一配置组件和编排行为的机制。它采用Go语言中常见的函数式选项（Functional Options）模式，允许以类型安全且灵活的方式传递配置。

选项可以作用于不同的层级：
- **全局选项**：影响整个编排的执行。
- **组件类型选项**：影响特定类型的所有组件（如所有`ChatModel`）。
- **节点选项**：仅影响图中的特定节点。

例如，可以通过`WithCallbacks`选项为一次执行添加回调处理器，通过`WithChatModelOption`为所有`ChatModel`节点设置温度参数，或通过`DesignateNode`将选项精确地指定给某个节点。

```go
// assign to All nodes
compiledGraph.Invoke(ctx, input, WithCallbacks(handler))

// assign only to ChatModel nodes
compiledGraph.Invoke(ctx, input, WithChatModelOption(WithTemperature(0.5))

// assign only to node_1
compiledGraph.Invoke(ctx, input, WithCallbacks(handler).DesignateNode("node_1"))
```

这种分层的选项系统使得配置既灵活又精确，能够满足从简单到复杂的各种配置需求。
